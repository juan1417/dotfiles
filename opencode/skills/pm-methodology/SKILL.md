# PM Methodology

Metodología de Project Management para gestión de requerimientos, planificación y seguimiento de proyectos de software.

## Uso

Activar cuando el usuario necesite: planificar un proyecto, definir alcance, crear roadmap, estimar esfuerzo, o gestionar requerimientos.

## Pasos

1. **Recopilar requerimientos** - Entender necesidades del negocio y del usuario
2. **Definir alcance** - Establecer límites claros del proyecto (in/out)
3. **Crear roadmap** - Planificar fases y milestones
4. **Estimar esfuerzo** - Usar story points o tiempo estimado
5. **Priorizar** - Aplicar MoSCoW o matriz impacto/esfuerzo
6. **Documentar** - Generar PLANNING.md con todo lo anterior

## Herramientas

- Análisis de requerimientos (historias de usuario, user stories)
- Definición de alcance (scope statement)
- Estimación (t-shirt sizing, planning poker)
- Seguimiento (burndown, velocity)

## Plantillas

```markdown
# PLANNING.md

## Objetivo
[Brief del proyecto]

## Alcance
### Incluido
- [Features]

### No incluido
- [Fuera de alcance]

## Roadmap
- Fase 1: [Descripción] - [Fecha]
- Fase 2: [Descripción] - [Fecha]

## Estimación
| Feature | Story Points | Prioridad |
|---------|-------------|-----------|
| [Name]  | [Points]    | [MoSCoW]  |
```

## Ejemplos

- "Necesito planificar el desarrollo de un e-commerce"
- "Crea un roadmap para el próximo trimestre"
- "Estima el esfuerzo para migrar la base de datos"

## Referencias

- Seguir convenciones de documentación existentes en el proyecto
- Integrar con ADRs para decisiones arquitectónicas
- Mantener el PLANNING.md actualizado durante el ciclo de vida
